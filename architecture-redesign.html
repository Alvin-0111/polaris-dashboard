Talos Dashboard 架构重构方案

从产品经理视角分析当前三栏布局的问题，并给出结构优化方案

1当前结构的核心问题
🔄

信息重复严重

左侧有数据概览，中间工作看板也有4统计指标；左侧有快捷操作，中间也有快捷操作；左侧有最近编辑，知识库看板也有最近笔记。用户看到的是重复信息，不是增量信息。

🎭

右侧面板职责不清

右侧详情面板既承担"任务详情展示"，又承担"今日待办+打卡+本周学习"的固定功能。当显示任务详情时，今日待办和打卡就被挤掉，用户无法同时看到任务详情和今日事项。

📦

左侧边栏功能过载

左侧边栏同时放了 Logo、搜索、数据概览、看板导航、快捷操作、最近编辑、底部操作，共7类功能。用户注意力被分散，导航反而不清晰，边栏变成了"什么都放一点"的杂物间。

📅

打卡模块位置尴尬

打卡放在右侧详情面板顶部，宽度只有320px，习惯列表显示不完整，本周日历也比较拥挤。打卡是高频日常功能，应该有更合适的位置和更充裕的展示空间。

🔀

看板切换成本高

工作/知识库/复习/日历四个看板是完全独立的，用户需要频繁切换才能看到不同维度的信息。实际上用户每天最关心的是"今天要做什么"，而不是分维度查看。

🎯

焦点任务与今日待办重复

中间有焦点任务卡片，右侧有今日待办列表，功能重叠。焦点任务应该是从今日待办中自动挑选的"最紧急最重要"的那一个，而不是独立的另一套数据。

3三个重构方案对比
方案 A · 保守优化

三栏职责重分配

保持三栏结构不变，但重新分配每栏的职责，解决信息重复和职责不清的问题。改动最小，风险最低。

✓ 优点
  • 改动最小，用户学习成本低
  • 不需要重构核心代码
  • 可以快速验证效果
✗ 缺点
  • 右侧详情与今日面板的冲突仍存在
  • 打卡模块空间仍然有限
  • 没有解决根本的架构问题
⭐ 推荐方案 · 平衡优化

顶部导航 + 主内容 + 今日面板

改为"顶部导航栏 + 中间主内容区 + 右侧固定今日面板"的结构。顶部放导航和全局操作，中间放当前看板核心内容，右侧固定放打卡+待办+学习，任务详情用弹窗或抽屉展示。

✓ 优点
  • 解决右侧详情与今日面板的冲突
  • 打卡和待办始终可见，符合日常使用习惯
  • 顶部导航更清晰，左侧空间释放给主内容
  • 主内容区更宽，甘特图和任务看板展示更好
  • 符合 Notion / Linear 等现代工具的交互模式
✗ 缺点
  • 需要重构布局代码，改动中等
  • 用户需要适应新的导航位置
  • 顶部高度会占用一些垂直空间
方案 C · 激进重构

单一主视图 + 可折叠面板

改为"单一主视图 + 左侧可折叠导航 + 右侧可折叠今日面板 + 浮动详情抽屉"的结构。所有面板都可折叠，主内容区可以最大化。最灵活，但改动最大。

✓ 优点
  • 主内容区可以最大化，适合深度工作
  • 所有面板可折叠，灵活性最高
  • 详情用抽屉，不占用固定空间
  • 符合专业工具（如 VS Code、Figma）的模式
✗ 缺点
  • 改动最大，需要重构核心布局逻辑
  • 折叠/展开的交互复杂度高
  • 用户学习成本最高
  • 可能过度设计，日常使用反而麻烦

决策 1：是否采用方案 B？

方案 B（顶部导航 + 主内容 + 今日面板）是我推荐的平衡方案。如果你倾向更保守（方案 A）或更灵活（方案 C），请告诉我。

❓

决策 2：任务详情用抽屉还是弹窗？

抽屉（从右侧滑出）更适合查看和编辑，不打断主内容；弹窗（居中）更适合聚焦操作，但会遮挡主内容。我推荐抽屉。

❓

决策 3：右侧今日面板是否可折叠？

可以加一个折叠按钮，需要专注工作时收起右侧面板，主内容区最大化。但会增加交互复杂度。我建议先做固定版本，后续再加折叠。

❓

决策 4：数据概览放在哪里？

方案 B 中，左侧的数据概览（4个统计卡片）需要重新安置。可以放在工作看板顶部（但要去掉重复的4统计指标），或者做成一个可折叠的统计面板。我建议放在工作看板顶部，替换原来的重复指标。
